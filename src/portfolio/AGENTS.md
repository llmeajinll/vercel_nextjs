# 포트폴리오 구현 규칙

[저장소 공통 규칙](../../AGENTS.md)을 함께 적용한다. UI 작업 전 다음 문서를 반드시 모두 읽는다.

1. [디자인 기본 규격](../../.agents/rules/design-foundations.md)
2. [컴포넌트와 페이지 구조](../../.agents/rules/design-components.md)
3. [공통 UI 구현 안내](ui/README.md)

화면 문구(`data.ts`)를 쓰거나 고칠 때는 [글쓰기 규칙](../../.agents/rules/writing.md)을 먼저 읽는다.

- 디자인 수치와 금지 사항은 `.agents/rules`에서만 관리한다. 이 파일이나 에이전트별 문서에 별도 수치를 복제하지 않는다. 기존 구현과 차이가 있으면 사용자 제공 디자인 기준이 우선한다.
- `Portfolio.tsx`는 라우팅과 화면 조합만 담당한다. 소개는 `ProjectIntro`, 배경과 과제는 `ProjectContext`를 사용한다.
- 제목·본문·라벨·칩·링크·행은 `ui/PortfolioUI.tsx`, 목록과 설명 블록은 `ui/Content.tsx`를 사용한다. 화면 조합부에서 스타일을 덮어쓰지 않는다.
- 역할이 다른 섹션 제목·행 라벨·메타정보·캡션을 구분한다. 새 변형이 필요하면 디자인 규칙에 해당 역할이 있는지 먼저 확인하고 공통 컴포넌트에서 관리한다.
- 첨부 시안의 문구와 수치를 모든 프로젝트에 복사하지 않는다. 개인·팀 기여, 서버·프론트엔드 역할, 과제 조건·실측 성과의 구분을 유지한다.
- 목차·이미지 확대·캐러셀·슬라이더 데모의 동작과 URL을 유지한다. 문서 정리 요청만으로 앱 전체를 다시 디자인하지 않는다.
- 공통 UI를 수정하면 영향을 받는 페이지의 크기·굵기·행간·간격·내용 시작점을 실제 브라우저에서 측정한다. 확인한 결과와 남은 차이를 구분해 보고한다.
