# 포트폴리오 스타일 유지

[저장소 공통 규칙](../../AGENTS.md)을 함께 적용한다. 아래 규칙은 `src/portfolio/` 영역의 세부 기준이며, 컴포넌트별 규격은 [UI 문서](ui/README.md)를 참고한다.

- 기존 스타일을 재사용한다. 새 화면·문구를 추가하면서 글자 크기, 굵기, 행간, 색상, 간격을 임의로 정하지 않는다.
- `Portfolio.tsx`는 라우팅과 화면 조합만 담당한다. 소개 영역은 `components/ProjectIntro.tsx`를 사용한다.
- 제목·본문·소제목·칩·링크·구분선이 있는 행은 `ui/PortfolioUI.tsx`, 목록과 설명 블록은 `ui/Content.tsx`를 사용한다. 컴포넌트의 스타일을 화면에서 덮어쓰지 않는다.
- 섹션 소제목은 **14px / font-weight 600 / line-height 21px / letter-spacing 0.14px**이다. ‘프로젝트 배경과 과제’, ‘역할과 담당 업무’, ‘기술 스택’, ‘테스트 및 협업’은 같은 `Label`을 사용한다. 과제 조건·팀 구조·프론트엔드 과제는 `ProjectContext` 한 섹션에서 설명한다. 소제목용 13px·15px 변형을 추가하지 않는다.
- 기간·역할 같은 메타정보 라벨은 별도 역할이므로 기존 12px 규격을 사용한다. 칩·캡션·목차를 섹션 소제목과 혼동하지 않는다.
- 파란 프로젝트 요약은 `ProjectSubtitle`의 `accent` 옵션을 사용한다. 기본 크기는 기존 20px이다.
- 새 변형이 필요한 경우 기존의 같은 역할을 먼저 찾고 브라우저의 computed style을 측정한다. 기존 컴포넌트에 용도가 명확한 옵션을 추가하고 `ui/README.md`에 기록한다.
- 공통 컴포넌트를 수정하면 데스크톱·모바일에서 크기·굵기·행간·간격을 측정하고 영향을 받는 페이지를 비교한다. 단순히 ‘비슷해 보인다’는 판단으로 완료하지 않는다.
- 콘텐츠, 개인·팀 기여 구분, URL, 목차·이미지 확대·슬라이더의 동작을 스타일 작업 중 임의로 변경하지 않는다.
