# 포트폴리오 규칙

포트폴리오 UI를 읽거나 수정하는 모든 에이전트는 아래 두 문서를 **작업 전에 모두 읽는다**.

1. [기본 규격](design-foundations.md): 색상, 서체, 글자 크기, 행간, 레이아웃, 간격, 형태
2. [컴포넌트와 페이지 구조](design-components.md): 블록 구성, 목록, 표, 기술 스택, 상세 페이지 순서, 금지 사항

포트폴리오 문구·프로젝트 소개·README처럼 외부 독자가 읽는 글을 쓰거나 고칠 때는 [글쓰기 규칙](writing.md)을 **작업 전에 읽는다**. 작업 모델, 독자, 문장 기준, 다 쓴 뒤 다시 읽는 절차를 이 문서에서 관리한다.

## 기준과 적용 범위

- 디자인 규칙의 출처는 사용자가 2026-11-19에 제공한 **「포트폴리오 디자인 시스템 — Foundations」**, **「컴포넌트와 페이지 구조 — Components」** 두 자료다. 기준 화면은 `/portfolio/nova`다.
- 이 규칙은 Nova·Ephyra·NEXT GACHA를 포함한 포트폴리오 UI에 적용한다. Todo 등 별도 앱의 디자인을 이 규칙으로 바꾸지 않는다.
- 사용자의 현재 명시적 지시를 우선한다. 그 밖의 경우 이 폴더의 디자인 규칙이 이전 시안·세션 설명·구현 안내보다 우선한다.
- 현재 코드에 다른 값이 남아 있다는 이유로 그 값을 새 작업의 기준으로 삼지 않는다. 수정할 영역에서 차이가 발견되면 이 규칙과 공통 컴포넌트를 기준으로 처리한다. 요청 범위 밖의 화면까지 임의로 일괄 수정하지 않는다.
- 숫자와 금지 사항은 이 두 규칙 문서에서 관리한다. `src/portfolio/ui/README.md`는 구현 위치와 사용법을 안내하며, 별도의 디자인 기준을 만들지 않는다.
- 이 폴더가 모든 도구에서 자동 로드된다고 가정하지 않는다. 루트 `AGENTS.md`, `CLAUDE.md`, `src/portfolio/AGENTS.md`의 필수 읽기 목록으로 연결한다.

## 변경과 검증

- 화면 조합에서는 기존 공통 컴포넌트를 사용하고, 임의의 크기·색상·여백으로 덮어쓰지 않는다.
- 새 컴포넌트가 필요하면 아래 두 문서의 역할과 규격을 먼저 확인하고 공통 UI 안에 추가한다. 자료에 없는 값을 추측해서 새 토큰으로 등록하지 않는다.
- 사용자 승인으로 기준을 바꾸는 경우 이 폴더의 해당 규칙과 구현 안내를 함께 갱신한다. 에이전트별로 다른 규칙 사본을 만들지 않는다.
- UI 변경은 최소 1440px·390px 브라우저에서 확인한다. 글자 크기·굵기·행간·자간·색상과 콘텐츠 시작 위치는 `getComputedStyle` 및 요소 좌표로 확인한다.
- 문서 정리만 한 경우 앱 전체를 수정하거나 불필요한 빌드·화면 테스트를 실행하지 않는다. 규칙의 수치, 문서 간 모순, 링크 경로를 확인한다.
